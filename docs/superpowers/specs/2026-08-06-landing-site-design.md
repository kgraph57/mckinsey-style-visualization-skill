# Landing Site — design contract

Date: 2026-08-06. Status: approved direction, implementation in progress.

## Goal

A dedicated single-page site for the skill, served from GitHub Pages at
`https://kgraph57.github.io/mckinsey-style-visualization-skill/`. Purpose:
**OSS adoption** — show the thing actually rendering (which the README cannot),
then funnel visitors to install and star.

Three locked decisions (from 2026-08-06 session):

1. **Purpose**: OSS landing page. Not a playground (no in-browser renderer),
   not a commercial page, not a docs hub.
2. **Hosting**: GitHub Pages + static files, living in this repository,
   artifacts committed and CI-drift-checked — the same discipline as the
   gallery SVGs.
3. **Language**: English site. Japanese capability is proven by embedding the
   `board-update-ja` deck as a live demo, not by site i18n.

## Concept: "Chaos → Clarity"

The page structure IS the product story. The top of the page is a rich,
scroll-driven Three.js scene: scattered fragments of notes, numbers, and chart
shards that **assemble into the actual ARR waterfall** as you scroll. Everything
below the hero is the product's own restrained visual system (navy `#15296B`,
white, 8px grid, Georgia serif headlines).

This resolves the brand tension honestly: a product roasted for decoration must
not ship a decorative site. The hero is not ornament — it is the sentence
"messy notes in, board-ready slides out" rendered as an experience. The moment
of convergence is the pitch; the calm below it is the proof.

## Non-goals

- No playground / live rendering (renderer is Python; a JS port is a separate
  project).
- No build step. No JS framework. No external requests at runtime (three.js is
  vendored; fonts are Georgia + system stacks, exactly like the renderer).
- No analytics, no cookie consent, no live GitHub API calls.
- No site i18n toggle, no custom domain (v1), no multi-page docs site.
- `docs/superpowers/` stays where it is; the site nav never links it.

## Information architecture (single page, in order)

1. **Hero** — Three.js chaos→clarity scene; headline "Messy notes in.
   Board-ready slides out."; install command with copy button; Star-on-GitHub
   link. Static SVG poster fallback for no-WebGL and `prefers-reduced-motion`.
2. **Live deck** — `examples/demo-deck.html` embedded in an iframe; caption
   notes arrow-key navigation and `p` → print → PDF.
3. **Pipeline** — notes → spec JSON → SVG → deck → PDF, four-step visual.
4. **Gallery** — all committed render SVGs as a grid; lightbox pairs each
   render with its source spec JSON side by side ("specs diff like code" made
   visible).
5. **CJK proof** — `board-update-ja` deck embedded live; copy on per-fullwidth
   wrapping and 稟議書/役員会 profiles.
6. **Four output modes** — deck / report / speaker script / article strip,
   each linking its committed `examples/demo-*.html`.
7. **Roasted by five design legends** — the 5.8/10 → every-fix-shipped story
   as score cards. Strongest persuasion asset in the README.
8. **60-second start** — terminal-styled copy block (clone → render → build).
9. **Footer** — Star CTA, MIT license, the not-affiliated-with-McKinsey
   disclaimer (legally required), repo links.

OGP: one committed `docs/site/og.png` (1200x630) + meta tags. Generated once
via headless browser screenshot of the hero fallback poster; not part of the
stdlib build.

## File layout

```
docs/                          # GitHub Pages root
  index.html                   # the single page
  site/
    css/tokens.css base.css sections.css
    js/main.js hero.js gallery.js lightbox.js
    vendor/three.module.js     # vendored, pinned version noted in header
    artifacts/                 # GENERATED by scripts/build_site.py, committed
      rendered/*.svg           # copy of assets/rendered/
      specs/*.json             # copy of examples/render-specs/
      demo-deck.html           # copy of examples/demo-deck.html (+ report/article/script)
      ja-deck.html             # built from templates/decks/board-update-ja/deck.json
      gallery-manifest.json    # [{file, title, pattern, spec}] derived from specs
    og.png
  superpowers/                 # existing, untouched
```

## scripts/build_site.py (stdlib only)

- Copies the committed artifacts above into `docs/site/artifacts/`.
- Builds `ja-deck.html` by calling the same functions `build_html_deck.py`
  uses (import, not subprocess).
- Derives `gallery-manifest.json` from the spec JSON files (title, pattern).
- `--check` regenerates into a temp dir and diffs; non-zero exit on drift.
- CI (`.github/workflows/ci.yml`) gains one step: `python3 scripts/build_site.py --check`.

## Design tokens (site mirrors the product)

From `references/style-system.md`: navy `#15296B`, secondary `#2563EB`, ink
`#000000`, greys `#374151 / #6B7280 / #D1D5DB`, fills `#F3F4F6 / #EFF3FB`,
risk `#B91C1C` (sparingly). Headlines Georgia serif; body system sans;
8px spacing unit. Emphasis ladder (fill > line > text) applies to section
design. No gold, no gradients on content surfaces, no purple.

## Hero best-of-N

Three hero concepts are built in parallel isolated worktrees, screenshotted,
and one is selected before integration:

- **A. Convergence** — static camera; hundreds of fragments fly into place as
  the waterfall + headline on scroll.
- **B. Corridor** — deck slides as drifting 3D planes in navy space; scroll
  dollies the camera through, ending on the waterfall head-on.
- **C. Ink to grid** — chaotic point cloud snaps onto an 8px lattice as the
  camera pushes in; ends flat, dissolving into the 2D page.

Performance budget: ≤ 60fps on an M1 Air, custom JS ≤ 100KB total,
three.module.js vendored (~600KB, the only heavy asset), no addons.

## Workflow

spec (this file) → writing-plans → hero best-of-N → foundation (tokens, base
CSS, index skeleton, build_site.py + CI) → parallel section implementation
(separate file ownership, zero shared-file edits) → integration → browser QA
→ code/security review → report. Human gates: hero selection, final diff
review before any push. Push and Pages enablement are manual owner actions.

## Known unknowns / risks

- Repo grows by ~600KB (vendored three.js) — accepted, Pages-served.
- `docs/superpowers/` becomes browsable at public URLs — already public in the
  repo; cosmetic only.
- iframe deck keyboard nav requires a click to focus — accepted, noted in
  caption copy.
- OGP PNG is a manually produced one-time asset — accepted, recipe recorded
  in the plan.
